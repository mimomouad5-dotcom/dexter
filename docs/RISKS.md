# سجل المخاطر المعمارية والتنفيذية (Risk Register) — Dexter Presentation Studio

| # | الخطر | الأثر | الاحتمالية | استراتيجية التخفيف والحل |
|---|---|---|---|---|
| **R1** | قيود python-pptx في دعم الحركات والانتقالات الأصلية | عالٍ | مؤكد | بناء طبقة حقن OOXML متخصصة عبر `lxml` مع سجل تأثيرات موثوق (`effects_registry.json`)، واقتصار الواجهة على التأثيرات المختبرة فعلياً (`verified: true`). |
| **R2** | عدم التطابق البصري التام بين معاينة الكانفاس وملف PPTX الناتج | عالٍ | متوسط | اعتماد نموذج بيانات موحد (`n23`) يستخدم وحدات القياس الرسمية لـ PowerPoint (EMU)، واستخدام مقاييس الخطوط الفعلية لمنع الفيض (Overflow). |
| **R3** | تشويه أو عدم انضباط النصوص العربية (RTL) في PowerPoint | متوسط | متوسط | ضبط خصائص اتجاه الفقرة `rtl="1"` على مستوى عقد OOXML في `a:pPr` واختيار خطوط عربية قياسية مفتوحة المصدر (مثل Cairo أو Noto Sans Arabic). |
| **R4** | عدم توفر خادم Ollama المحلي على جهاز المستخدم أو ضعف موارد العتاد | متوسط | متوسط | فحص بيئة التشغيل وإرشاد المستخدم بخطوات التثبيت والنماذج الخفيفة الموصى بها، مع إتاحة خيار المزودات الخارجية الآمنة بموافقة مسبقة. |
| **R5** | استهلاك موارد النظام أو تجمد التطبيق أثناء فهرسة مكتبات ضخمة | متوسط | منخفض | تنفيذ الفهرسة في عمليات خلفية مقسمة إلى دفعات (Batches)، ودعم الإلغاء الفوري دون إفساد قاعدة البيانات، مع حدود أمان ضد ملفات zip bombs والملفات التالفة. |
| **R6** | تسريب مفاتيح API السرية عبر السجلات أو ملفات المشاريع | حرج | منخفض | منع تخزين المفاتيح في أي ملف، تشفيرها في Windows Credential Manager / safeStorage، واستخدام مرشح حجب تلقائي (Redaction Safe Logger `n32`). |
| **R7** | تباين واجهات المزودات السحابية الخارجية (OpenAI, Anthropic, Gemini...) | منخفض | متوسط | تصميم نمط محول مستقل (Adapter Pattern `n37`) لكل مزود مع عزل كامل لمنطق الطلب واختبارات الاتصال. |
