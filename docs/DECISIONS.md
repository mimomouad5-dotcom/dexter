# سجل القرارات المعمارية والتقنية (ADR) — Dexter Presentation Studio

## DEC-001: اختيار إطار عمل الواجهة وسطح المكتب (Electron vs. Tauri vs. WPF/.NET)
- **السياق:** التطبيق يحتاج واجهة تفاعلية متطورة تدعم RTL/LTR، وتحرير كانفاس غني مع Undo/Redo، ومعاينة بصرية، وتشغيل خدمة بايثون محلية على Windows 10/11 x64.
- **الخيارات المدروسة:**
  1. **Electron (React + TypeScript):** نضج تام، سهولة دعم الكانفاس وRTL/LTR، عزل أمني عبر `contextIsolation: true` و`sandbox: true`، إدارة عمليات موثوقة لـ Python subprocess عبر `child_process`، ومكتبات غنية لتخزين الأسرار (`safeStorage`).
  2. **Tauri (Rust + React):** استهلاك ذاكرة أقل وحجم حزمة أصغر، لكنه يتطلب أدوات تجميع Rust على بيئات التطوير، وتعقيد أكبر في إدارة دورة حياة خدمة Python كعملية فرعية مع التوكنات ومعالجة أخطاء Windows.
  3. **WPF / .NET (C#):** أصلي على Windows، لكنه يفتقر إلى مرونة واجهات الويب المعاصرة والمنظومة الواسعة من أدوات التصميم وReact 19 ومكونات الكانفاس المتطورة.
- **القرار المعتمد:** اعتماد **Electron (React + TypeScript)** مع عزل أمني صارم: `nodeIntegration: false`، و`sandbox: true`، وجسر Preload مقيد بـ Zod validation (`n9`).
- **العواقب والتخفيف:** زيادة حجم الحزمة الأولية؛ التخفيف باستخدام ضغط الحزم وتشغيل Python عبر بيئة مدمجة (embeddable) دون تثبيت نظام كامل.

## DEC-002: طريقة تجميع وتوزيع محرك Python (PyInstaller vs Embeddable Python)
- **السياق:** يحتاج التطبيق إلى تشغيل خدمة FastAPI على جهاز المستخدم النهائي (Windows 10/11) دون اشتراط تثبيت مسبق للبايثون.
- **الخيارات المدروسة:**
  1. **Embeddable Python (النسخة الرسمية المدمجة من python.org):** تشغيل مباشر لنصوص البايثون وبيئتها الافتراضية مع ملف `python._pth` محدد بدقة. سريعة الإقلاع وشفافة في التحديث وسهلة الفحص.
  2. **PyInstaller (حزمة ثنائية واحدة One-file / One-dir):** تجميع كامل لـ FastAPI ومكتبة python-pptx داخل مجلد تنفيذي.
- **القرار المعتمد:** دعم بيئة **Embeddable Python أو PyInstaller (One-dir)** كخيار مفضل لتجنب أوقات فك الضغط البطيئة لـ One-file وضمان عمل مكتبات C مثل lxml وPillow بسلاسة.

## DEC-003: مخزن الأسرار على نظام Windows (Credential Manager vs Electron safeStorage)
- **السياق:** التطبيق يمنع حفظ مفاتيح API السرية في الملفات النصية أو قواعد البيانات أو السجلات أو Git.
- **الخيارات المدروسة:**
  1. **Electron safeStorage API:** مدمجة في Electron، تعتمد مباشرة على Windows Data Protection API (DPAPI)، لا تتطلب تبعيات C++ إضافية قد تفشل في البناء، مشفرة لكل مستخدم ويندوز.
  2. **keytar (Windows Credential Manager):** مكتبة قديمة غير مستمرة الصيانة قد تواجه مشاكل توافق مع إصدارات Node الحديثة.
- **القرار المعتمد:** اعتماد **Electron `safeStorage`** مع تشفير DPAPI الأصلي لويندوز، مع واجهة تجريد تتيح التبديل إن لزم الأمر.

## DEC-004: نموذج التصدير وحقن الحركات في PowerPoint (python-pptx + OOXML Injection)
- **السياق:** مكتبة `python-pptx` القياسية تدعم النصوص والأشكال والجداول والصور والرسوم البيانية، لكنها تفتقر إلى واجهة برمجة مباشرة لإضافة حركات العناصر (Custom Animations) وانتقالات الشرائح (Slide Transitions).
- **القرار المعتمد:** اعتماد **python-pptx** لبناء هيكل العرض التقديمي الأصلي والعناصر القابلة للتحرير، مع استخدام **حقن OOXML المباشر (`lxml`)** في شجرة الـ XML الخاصة بالشرائح (`p:timing` و`p:transition`) للتأثيرات التي تم اختبارها والتحقق منها فقط (`verified: true` في `n28`).

## DEC-005: استراتيجية فهرسة المكتبة وكشف التكرار واستخراج بيانات القوالب (Phase 6 Best Practices)
- **السياق:** تتطلب المرحلة 6 مسح مجلد المكتبة `n42` بكفاءة عالية، تصنيف الملفات، كشف الملفات المكررة والتالفة، واستخراج بيانات القوالب وعروض PPTX، دون إبطاء الواجهة ودون إفساد قاعدة البيانات عند الإلغاء.
- **الحلول المبحوثة في مجتمعات GitHub والمطورين:**
  1. **التصفية المتدرجة لكشف التكرار (3-Stage Deduplication):**
     - المرحلة 1 (Size Pre-filtering): استبعاد الملفات فريدة الحجم فوراً دون قراءة أي بايت منها (توفير >85% من عمليات I/O).
     - المرحلة 2 (Head/Tail Quick Hash): حساب هاش سريع لأول 4KB وآخر 4KB للملفات المتطابقة في الحجم فقط.
     - المرحلة 3 (Full SHA-256 Streaming): حساب الهاش التام عبر دفق 64KB للملفات المتطابقة في المرحلتين السابقتين.
  2. **التحقق بالبصمات السحرية (Magic Bytes / Header Signatures):**
     - عدم الثقة بالامتداد الصرف لتفادي هجمات الخداع والملفات التالفة.
     - التحقق من ترويسات `PK\x03\x04` وفحص أجزاء OOXML المعتمدة لملفات PPTX.
     - التحقق من `%PDF-` لملفات PDF، و`\x89PNG` و`\xff\xd8\xff` للصور، والترميز النصي لـ Markdown/Text.
  3. **استخراج بيانات القوالب الذكية (Template Metadata Extraction):**
     - فحص عدد الشرائح ونسبة العرض (16:9 مقابل 4:3) وعدد النصوص والأشكال والرسوم البيانية والصور.
     - استخراج عناوين الشرائح والقوالب لاقتراحها الذكي للمستخدم.
  4. **الأمان ودعم الإلغاء والمهام الخلفية (Cancellation & Transaction Safety):**
     - تعطيل تتبع الروابط الرمزية (`follow_symlinks=False`) لمنع الحلقات اللانهائية والـ Symlink Traversal.
     - الفحص الدوري لراية الإلغاء (`task.is_cancelled`) وبث أحداث التقدم (`TaskProgress`).
     - تنفيذ العمليات على دفعات SQLite مع دعم Rollback التام عند الإلغاء.
- **القرار المعتمد وترشيح الطريقة المثلى:** اعتماد خط أنابيب التصفية ثلاثي المراحل، مع وحدة تصنيف بصمات سحرية مخصصة، واستخراج بيانات القوالب المتقدمة، وربطها بمسارات الـ API في خدمة المحرك `services/engine` وواجهة المكتبة `n6` في سطح المكتب.
